## Pocket Grove

The full-game candidate expands the user-tested MVP with twelve original figures across two
collections, automatic display income, a fourth-slot unlock, three room palettes, collection
plaques, daily boxes/goals, persistent profiles, and same-server visits. A tabbed interface
replaces the MVP menu; scrolling follows measured content height so every figure is reachable.

In current product terminology, the implemented earning shelf is the **Display**. Planned
non-economic customizable **Showrooms** and the Showroom Gallery are documented separately and
are not implemented yet; see [Display and Showrooms](docs/DISPLAY_AND_SHOWROOMS.md).

Open `RobloxWorkspace.rbxlx` in Studio to try it. Studio defaults to **unsaved preview**;
live servers require a successful persistent load. See [full-game scope](docs/FULL_GAME.md),
[architecture](docs/ARCHITECTURE.md), [economy](docs/ECONOMY.md), and
[testing and release setup](docs/OPERATIONS.md). The candidate is not published, and its new
Studio/device/live-storage tests have not been run by the agent.

## Setup and checks
Run these commands from the repository root with Rokit on PATH:

```bash
rokit install
wally install
stylua src
stylua --check src
selene src
rojo build default.project.json -o RobloxWorkspace.rbxlx
```

Tool versions are pinned in `rokit.toml`. Wally has no dependencies yet;
`wally install` resolves the lockfile. The Packages mapping uses an explicit
Folder and optional path so builds work with zero dependencies, when Wally
leaves the directory absent. Commit `wally.lock` when it changes, but not generated
package contents. Selene may download its Roblox
API cache on first run. These checks do not replace Luau type diagnostics or
Studio playtests.

VS Code format-on-save uses the installed StyLua extension and looks for the
Rokit formatter on PATH. The existing 100-column, tab-indented, Windows line
ending style is retained, with Luau syntax selected explicitly. Use the installed
Luau Language Server for type diagnostics.

## Roblox Studio

Open `RobloxWorkspace.rbxlx` to inspect a fresh build, or continue using your
existing connected Studio place. Start the Rojo server:

```bash
rojo serve default.project.json
```

Connect through the Studio Rojo plugin. If the server was already running when
the project mapping changed, restart it and reconnect. Confirm that
`ReplicatedStorage.Packages` appears alongside `Shared`, then use Play to check
the main-plot Display and Output. Open a box, place the selected figure, and watch Coins increase.
No gameplay dependencies are installed. The HUD identifies whether you are in unsaved Studio preview or using persistent progress.

Follow [the full-game test and release checklist](docs/OPERATIONS.md) before release.

[Rojo documentation](https://rojo.space/docs) for Rojo usage.

## Deterministic gameplay tests

The repository-local harness runs the actual Rules, Protocol, Transactions, Profile, Persistence
and Scroll modules using
standalone Luau. Python only rewrites Roblox module paths in ignored `build/tests` copies and
stubs catalog colors plus scrolling property/signal construction; it does not reimplement gameplay. No test grants or test
runner are mapped into the game.

```powershell
python tests/run.py build/tools/luau/luau.exe
```

The implementation was checked with the official standalone Luau 0.739 executable in that
ignored path. A separately installed Luau executable can be passed instead. This tool is for
verification only; it is not a Wally dependency or a replacement for Studio testing.
The suite covers transaction conservation, income, reservation/recycling rules, redemption,
roll boundaries, malformed payloads, replay/stale requests, rate limits, invalid configs,
profile migration, conflicting leases, lost save replies, failed storage calls and scroll sizing.
